## Project

FormAI mobile app: the React Native app (iOS and Android) used by gym **clients** (today's routine, set logging, history, machine recognition). The web app for trainers lives in `formai-web-app` and the backend in `formai-api`; both apps reach the backend through `/api`.

## Commands

```bash
npm start            # Metro bundler
npm run ios          # build and run on the iOS simulator
npm run android      # build and run on the Android emulator
npm run typecheck    # tsc --noEmit
npm run lint         # ESLint + Prettier + TSDoc syntax
npm test             # Jest
npx jest __tests__/useCounter.test.tsx       # one test file
npx jest -t "adds one on increment"          # one test by name
(cd ios && bundle exec pod install)          # after adding a native dependency (or: pod install)
npx react-native-asset                       # after adding a font to assets/fonts
```

This is a bare React Native project created with the Community CLI. **Expo is not used**: no Expo SDK targets React Native 0.87.

## Architecture

Layered, one direction only:

```
App → Screens → Components
        │
        ▼
      Hooks → Services → Backend/API
```

- `src/screens/` compose components and get data and actions from hooks. A screen never imports `services`.
- `src/components/` are presentational: data in through props, events out through callbacks. They never import `services`, data hooks or `context`. `ui/` holds the design-system primitives, `layout/` the navigation and structure, `<feature>/` the components of one feature.
- `src/hooks/` own state and use cases and are the only bridge to `services`.
- `src/services/` is the only layer that talks to the backend, always through `apiClient` (`services/api-client.ts`). The base URL lives in `services/config.ts` because React Native does not read `.env` files.
- `src/context/` is for state shared by several screens only; `src/utils/` and `src/types/` depend on nothing above them.
- Every layer folder has a `README.md` with its rules; read it before adding files to that layer.
- Imports use the `@/` alias for `src/` (Babel `module-resolver` + `tsconfig` paths). `index.js` registers `src/App.tsx`.

## Design system and styling

- Tailwind CSS v4 through **Uniwind**, configured in `metro.config.js` (it must stay the outermost Metro wrapper). `src/global.css` is the CSS entry and is imported in `src/App.tsx`.
- `src/tokens.css` holds the design tokens generated from the Figma file `formai_design_system`. **It must stay byte-identical to `formai-web-app/src/tokens.css`**: change both together.
- Only token utilities exist (`bg-primary`, `text-content-secondary`, `text-title`, `p-xl`, `shadow-card`). No hex colors or loose measures in screens or feature components; arbitrary values only inside `components/ui` and `components/layout`.
- `className` works only on React Native **core** components. Components from other libraries (for example `SafeAreaView` from `react-native-safe-area-context`) ignore it: wrap them in a core `View`.
- Each font weight is its own family (`font-sans`, `font-sans-semibold`, `font-sans-bold`, `font-sans-extrabold`), so text always goes through `<Text variant="…">`. Icons are Material Symbols Rounded ligatures through `<Icon name="…" />`.
- Color props that are not styles use Uniwind's `accent-*` classes (`colorClassName="accent-primary"`).
- `components/ui` exposes the same component API as the web app (same names, props and variants; `onPress` here, `onClick` there). Variant types live in `src/types/ui.ts`, shared with web. The default variant always uses the primary color.
- `src/types/uniwind-types.d.ts` is generated by Uniwind when Metro starts; it is committed and must not be edited.
- Mobile-first: the base layout is the phone in portrait; add wider layouts with min-width prefixes.

## Platform pitfalls

- Verify changes on **both** iOS and Android: a value accepted by one can crash the other (Android rejects `accessibilityRole="tabbar"`; use `tablist`).
- In Jest there are no native modules: `jest/setup.js` mocks `react-native-safe-area-context` and `*.css` maps to an empty module.

## Documentation standard

- Comments and identifiers are in **English**; interface copy is in Spanish.
- TSDoc on everything exported. Every source file starts with a header comment carrying `@author` (the git user who created the file) and `@packageDocumentation`. Props are documented field by field in the props interface, with `@defaultValue` where there is a default.
- `@author` is a custom tag declared in `tsdoc.json`; ESLint enforces the syntax with `tsdoc/syntax`.

## Versions

React Native is pinned to **0.87.1**, React to **19.3.0** and Tailwind CSS to **4.3.3**; do not change them without the owner's approval. Check current documentation before using an API or adding a dependency, and confirm that a native library supports React Native 0.87 before installing it.
